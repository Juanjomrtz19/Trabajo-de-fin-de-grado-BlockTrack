\section{Arquitectura software}
Elegir bien la arquitectura que se va a utilizar en un proyecto de ingeniería de software como este es de vital importancia, ya que la elección de una arquitectura inadecuada puede llegar a crear insatisfacción en el cliente final.

Según el estudio \textbf{A Survey on the Integration of Blockchains and Databases} hay tres arquitecturas que podriamos utilizar para dar una solución al problema de este proyecto:
\begin{itemize}
    \item \textbf{Blockchain orientada a base de datos:} Añade características de las bases de datos como  modelo relacional o índices y consultas eficientes entre otras a la red blockchain.
    \item \textbf{Base de datos orientada a blockchain:} Añade características de blockchain a una base de datos tales como inmutabilidad o consenso distribuido entre otras a la base de datos.
    \item \textbf{Sistemas híbridos:} Integracion equilibrada entre ambos modelos donde la idea es utilizar una base de datos para operaciones comunes y blockchain para información crítica de la lógica de negocio.
\end{itemize}

Para este caso se ha escogido el enfoque de \textbf{Sistema híbrido} debido a que lo mas eficiente es que en la red de blockchain solo se almacene lo esencial, el resto de datos pesados que se necesitan para el correcto funcionamiento de la aplicación se almacenaran en una base de datos tradicional.\\

Teniendo lo discutido anteriormente en cuenta la arquitectura software elegida para este proyecto será una arquitectura a 3 niveles o capas tradicional al que se le añade una capa extra para la blockchain. 
Esta arquitectura es adecuada para este proyecto ya que permite separar las distintas responsabilidades de la aplicación en capas independientes, facilitando el mantenimiento y escalabilidad del sistema.
Las capas son las siguientes:
\begin{itemize}
    \item \textbf{Capa de presentación (Frontend):} Es la capa encargada de la interacción con el usuario. En esta capa se encuentran todas las interfaces gráficas que permiten al usuario interactuar con la aplicación.
    \item \textbf{Capa de lógica de negocio (Backend):} Es la capa encargada de procesar la lógica de negocio de la aplicación. Esta capa recibe las peticiones del frontend, procesa la información y devuelve los resultados al usuario.
    \item \textbf{Capa de datos (Base de datos):} Es la capa encargada de almacenar y gestionar los datos de la aplicación. Esta capa se encarga de guardar toda la información necesaria para el correcto funcionamiento de la aplicación.
    \item \textbf{Capa blockchain:} Es la capa encargada de gestionar la tecnología blockchain utilizada en el proyecto. Esta capa se encarga de registrar las transacciones y datos críticos en la red de blockchain para garantizar la inmutabilidad, trazabilidad y seguridad de la información.
\end{itemize}

\subsection{Comunicación entre capas}
La comunicación entre el frontend y el backend se realiza mediante peticiones HTTP a una API RESTFull. El formato de la respuesta que envía el backend será en formato JSON.\\
La comunicación entre el backend y la capa blockchain se realizará a través de un \textit{proveedor de acceso a la red blockchain} (nodo), utilizando llamadas RPC estándar.\\
La comunicación entre el backend y la base de datos se realizará mediante un ORM (Object-Relational Mapping) que permitirá mapear las entidades del modelo de datos a tablas en la base de datos relacional.\\

Existen varias herramientas que permiten asegurarnos que el código se comporta correctamente en distintas situaciones en react. Las más famosas son:

\subsection{Base de datos}
Para saber que opción coger hay que diferenciar los dos principales tipos de base de datos que hay:
\begin{itemize}
    \item \textbf{Bases de datos relacionales}: Son un tipo de base de datos que almacenan los datos en formato de tabla, es decir organizan los datos en filas y columnas. Donde cada fila hace referencia a un registro con un ID único y cada columna hace referencia a un atributo de cada registro. Las bases de datos relaciones facilitan la creación de relación entre las distintas entidades de datos. \url{https://www.oracle.com/es/database/what-is-a-relational-database/}
    \item \textbf{Bases de datos no relacionales}: Este tipo de base de datos almacenan datos de forma diferente al formato de tablas mencionado. Utilizan su propio esquema para almacenar los datos y escalan fácilmente con grandes cantidades de datos y cargas de usuario. En este tipo de base de datos es mas complicado gestionar las relaciones entre entidades aumentando la complejidad en consultas complejas en las que esten implicadas relaciones. 
    \url{https://www.mongodb.com/es/resources/basics/databases/nosql-explained}
\end{itemize}

\section{Selección de la red blockchain}
Hay distintas tecnologías blockchain que se pueden utilizar para este proyecto. Algunas de las más populares son:
Ethereum, Hyperledger Fabric, Solana, Binance Smart Chain, entre otras.
Después de evaluar las distintas opciones, se ha decidido utilizar Ethereum debido a su amplia adopción, robusta infraestructura y soporte para contratos inteligentes.
\subsection{Ethereum}
Ethereum es una plataforma de blockchain de código abierto que permite la creación de contratos inteligentes y aplicaciones descentralizadas (dApps). Su criptomoneda nativa es el Ether (ETH). Ethereum ha sido pionera en la implementación de contratos inteligentes, lo que permite a los desarrolladores crear aplicaciones complejas que se ejecutan en su red. Además, cuenta con una gran comunidad de desarrolladores y una amplia gama de herramientas y bibliotecas que facilitan el desarrollo en su ecosistema. \hyperlink{ethereum}{https://ethereum.org}

\subsection{Contratos inteligentes}
Los contratos inteligentes son programas informáticos que se ejecutan automáticamente en una red de blockchain
cuando se cumplen ciertas condiciones predefinidas. Estos contratos permiten la automatización de acuerdos y
transacciones sin necesidad de intermediarios, lo que reduce costos y aumenta la eficiencia. Los contratos
inteligentes son inmutables y transparentes, lo que significa que una vez desplegados en la blockchain,
no pueden ser modificados y su código es accesible para todos los participantes de la red. \hyperlink{smartcontracts}{https://ethereum.org/en/developers/docs/smart-contracts/}

Para el desarrollo de los contratos inteligentes se utilizará el lenguaje de programación Solidity, que es el lenguaje
más popular y ampliamente utilizado para escribir contratos inteligentes en la red Ethereum. Solidity es un
lenguaje de alto nivel similar a c++, lo que facilita su aprendizaje para desarrolladores con experiencia en
otros lenguajes de programación. \hyperlink{solidity}{https://docs.soliditylang.org/en/v0.8.20/}

El desarrollo y la idea detrás de la programación de los contratos inteligentes es muy parecida a la programación
orientada a objetos, donde se definen clases (contratos) con atributos (variables de estado) y métodos.

\subsection{Diseño de contratos inteligentes para Blocktrack}
La idea principal de estos contratos inteligentes es registrar los envíos realizados en la plataforma BlockTrack, 
con el objetivo de disponer de un registro inmutable y transparente de cada transacción logística. Para ello,
se desarrolla un contrato inteligente denominado Envio, encargado de gestionar la información y el 
estado de cada envío a lo largo de su ciclo de vida dentro del sistema.\\

No obstante, para garantizar un mayor control y trazabilidad sobre los distintos contratos de envío desplegados, 
se define un segundo contrato inteligente denominado EnvioFactory. Este contrato actúa como fábrica y gestor central, 
responsable de crear nuevas instancias del contrato Envio y de mantener un registro de todas ellas en la red. 
De este modo, se facilita la supervisión global de los envíos registrados y se asegura la coherencia e 
integridad del sistema dentro de la plataforma BlockTrack.\\

\subsection{Por qué garantiza la confianza y trazabilidad.}
La plataforma registra en la red blockchain los hitos clave del ciclo de vida del envío (creación, aceptación, cambios de estado, transferencias de custodia y entrega) como eventos y estado on-chain. Cada operación está firmada por la dirección del actor correspondiente, lo que aporta no repudio, y queda ordenada e inmutable en la cadena. Las reglas del contrato inteligente garantizan que únicamente los actores autorizados pueden ejecutar cada transición (p. ej., solo el custodio actual puede transferir custodia y solo el receptor puede marcar la entrega). En caso de discrepancias, la información on-chain —respaldada por firmas y consenso— prevalece sobre declaraciones off-chain, proporcionando una fuente de verdad verificable para auditoría y resolución de conflictos, sin exponer datos personales en la cadena.

\subsection{Algoritmo de consenso utilizado por ethereum}

Según \cite{documentacionEthereum} un mecanismo de consenso en un bloque de ideas, protocolos e incentivos
diseñados para lograr la concordancia entre los nodos distribuidos sobre el estado de una red blockchain.\\

Por consenso se entiende a que se ha alcanzado un acuerdo general. Esta misma idea se traslada a ethereum,
donde llegar a un consenso significa que al menos el 66\% de los nodos de la red están de acuerdo en el estado
de la blockchain.\\ 

Anteriormente ethereum utilizaba como algoritmo de consenso Proof of Work (PoW) pero desde 2022 ha adoptado
Proof of Stake (PoS) como su mecanismo de consenso principal.

En PoS, los participantes que desean asegurar la red actúan como \textit{validadores} y deben bloquear una cantidad de ETH (\textit{stake}) a modo de fianza. A partir de ahí, el consenso se articula con cuatro piezas sencillas:

\begin{itemize}
\item \textbf{Selección de proponentes:} en cada “turno”, el protocolo elige de forma aleatoria a un validador para proponer un bloque con transacciones válidas.
\item \textbf{Votaciones:} el resto de validadores asignados a ese turno verifican y votan tanto el bloque propuesto como la “cabeza” de la cadena que consideran correcta.
\item \textbf{Incentivos:} los validadores ganan recompensas si proponen y votan a tiempo y correctamente; y reciben penalizaciones si llegan tarde, están inactivos o emiten votos incoherentes. Las conductas deshonestas graves pueden conllevar pérdida de parte del stake.
\item \textbf{Convergencia y finalidad:} las reglas de elección de bifurcación priorizan la rama con más apoyo ponderado por \textit{stake} (la “más fuerte” por votos recientes). Además, el protocolo marca puntos de control por épocas: cuando una supermayoría consistente los respalda, los bloques quedan justificados y, después, finalizados (económicamente muy costoso revertirlos).
\end{itemize}

Intuitivamente, PoS traslada la seguridad a un terreno criptoeconómico: quien participa debe poner “algo valioso” en juego (su ETH). El diseño de recompensas y sanciones alinea incentivos para que resulte rentable actuar honestamente y prohibitivo atacar el consenso. En situaciones excepcionales (p.,ej., una falla grave), la coordinación social de clientes, operadores y desarrolladores sirve de última línea de defensa para preservar una única cadena legítima.

\subsection{Patrones de diseño visual}
\begin{itemize}
    \item \textbf{Responsive Web Design:} El diseño de la apliación se adapta a diferentes tamaños de pantalla y dispositivos,
    asegurando una experiencia de usuario óptima tanto en ordenadores de escritorio como en dispositivos móviles. Es importante ya que los transportistas
    necesitarán acceder a la aplicación desde sus teléfono móviles.\\

    \item \textbf{Arquitectura basada en componentes:} Las pantallas de la aplicación más complejas se dividen o se construyen 
    a partir de componentes reutilizables, lo que facilita el mantenimiento y la escalabilidad del código. Al reutilizar estos componentes más atómicos
    se consigue una mayor coherencia visual en toda la aplicación.\\
\end{itemize}

\subsection{Colores y tipografía escogidos}
Para la paleta de colores de la aplicación se han cogido colores azules y anaranjados. El azul transmite confianza, seguridad
y profesionalismo, valores que son fundamentales en una plataforma de seguimiento de envíos. El naranja aporta un toque
de energía, dinamismo y accesibilidad, haciendo que la interfaz sea más atractiva y amigable para los usuarios.\\

Además se han establecido un color de advertencia (amarillo), un color de error(rojo) y un color de éxito (verde) para
diferenciar los distintos estados de las acciones realizadas por los usuarios en la aplicación.\\
